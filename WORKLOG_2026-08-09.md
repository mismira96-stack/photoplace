## Next Recommended Work

### P0 - Sort History Search

User need:

- 정리 기록이 많아지면 원하는 장소를 드래그로 찾기 어렵다.

MVP:

- Add a search bar to the sort history/recent places screen.
- Filter already loaded `StoredAlbumSummary` records in memory.
- Search by album/place name, country, admin/address text, and visible date text if practical.
- Tapping a result opens the matching detail screen.
- Do not scan MediaStore on every keystroke.

Implementation guardrail:

- Do not add more logic directly into `MainActivity` if avoidable.
- Prefer extracting a small search/filter helper first.

### P0 - No-Location UX

Problem:

- Users with many no-GPS photos repeatedly analyze the same files.

Preferred direction:

- Do not move no-location files by default.
- Ask during/after preview only when no-location count is meaningful.
- Default OFF.
- Explain clearly that file location changes but photos are not deleted.

Candidate copy:

- `위치 정보 없는 항목 2,034개`
- `다음 정리 때 다시 검사하지 않도록 별도 폴더로 이동할까요?`
- Checkbox: `위치 정보 없는 항목을 PhotoPlace/위치 없음 폴더로 이동`
- Warning: `원본 파일 위치가 바뀝니다. 사진은 삭제되지 않으며 갤러리에서 계속 볼 수 있어요.`

### P0/P1 - International Address Normalization

Problem:

- Japan trip revealed that localized Geocoder strings are not stable enough.
- Avoid fixing overseas places by continuously adding one-off aliases.

Direction:

- Add an `AddressNormalizer`-like layer before final album naming.
- Separate stable key from display name.
- Overseas subLocality/ward alone must not become a final album name.
- Example direction:
  - stable key: `JP|Hokkaido|Sapporo`
  - display name: `삿포로`

### P1 - Result/Detail UI Consistency

- Result/detail screens still feel less polished than Home.
- Keep auditing hidden screens as they are discovered.
- Buttons should use a consistent One UI-like tone:
  - light line icons
  - restrained color
  - clear primary/secondary hierarchy

### P1 - Personal Place MVP

- Continue with design first.
- Personal Place should be user-confirmed, not automatic POI promotion.
- Do not auto-rename or move files when saving a personal place.
- Gemini can help with analysis/design; Codex should own final implementation and device verification.
