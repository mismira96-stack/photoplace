## Memory Media Resolver — Source Selection Slice

- Added `MemoryMediaSourcePolicy` as a pure-Java source-selection contract for an exact Memory OrganizationLink, Gallery output lookup result, and live Discovery availability.
- A usable exact `SUCCESS`/`PARTIAL` Memory link with a confirmed Gallery output wins as the sole source; confirmed missing output falls back to live Discovery refs; no available source returns empty.
- A failed Gallery lookup is distinct from confirmed absence and returns `UNAVAILABLE` rather than silently falling back to a potentially stale/duplicate Discovery source.
- Added JVM tests for exact-link precedence/no union, missing-output fallback, lookup failure, absent link, unusable `MISSING` link, and empty state.
- This is policy/model/test groundwork only. It does not query MediaStore, build photo sections, connect UI, change OrganizationLinks, or mutate Gallery/user media. The shared resolver and internal viewer remain P0.
- Verification: `testDebugUnitTest` PASS, `assembleDebug` PASS, and `git diff --check` PASS. No device install or media operation was needed because this slice is pure source-selection policy with no UI/runtime integration.
- Antigravity reviewed `REVIEW_REQUEST_Memory_Media_Source_Policy_2026-09-14.md` and approved the policy slice. Review report: `REVIEW_Memory_Media_Source_Policy_2026-09-14.md`. It confirmed `MainActivity` is unchanged, exact Gallery output takes exclusive precedence, lookup failure does not silently fall back, and invalid/Collection/MISSING links are rejected.
- Follow-up risk recorded: because `PARTIAL` is considered usable, Gallery-only projection can omit refs that failed to copy. Originals remain protected; before resolver release, expose partial/retry state or define a safe per-media reconciliation without unconditional union.
