## No-Location Repeated Analysis Review

Current finding:

- The app still queries and loops over the selected MediaStore source inventory on each analysis run.
- This is expected because the app must know which files currently exist in the selected folders.
- The expensive part to optimize is not the inventory query itself, but repeated `readLocation()` / EXIF / metadata / geocoder work for unchanged files.
- Existing `NoLocationCache` remains disabled by `isNoLocationCacheEnabled() == false`.

Gemini design review conclusion:

- A no-location cache v2 is reasonable, but should not be enabled as a quick patch.
- Cache hit must skip only the expensive location-read path, not remove the media item from the preview inventory.
- Cache hit must still create a `PhotoItem(noLocation=true)` so the user sees the no-location count.
- Cache hit must remain excluded from Memory Browser groups and album organization candidates.

Required v2 safety rules before implementation:

- Signature must include at least source URI, display name, date modified, date added, datetaken, media kind, and preferably size/duration/mediaStoreId.
- If MediaStore has latitude/longitude, never trust the no-location cache; re-run location analysis.
- Any meaningful signature mismatch is a cache miss.
- Include schema version and policy version so old entries can be invalidated.
- Prefer file-backed JSON with temp/write + backup recovery over SharedPreferences v1.

Required tests before enabling:

- new files are not hidden by cache
- changed URI/modified/size invalidates cache
- copied/moved media misses cache
- MediaStore GPS appearing later forces reanalysis
- cache hit keeps no-location preview count visible
- corrupt cache restores or safely resets
- policy version changes invalidate old entries

Decision:

- Keep this as a separate performance/safety patch after the Memory Browsing MVP is stable.

## Memory Merge Safety Follow-Up

  - organized-only exclusion in discovery browser
  - matching organized album merge
  - same country/place but different admin and non-overlapping dates not merging
  - date-overlap merge even if admin differs
