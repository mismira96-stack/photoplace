## Code Added

Added:

- `MemoryRepository`
- `MemoryRepositoryTest`

Behavior:

- Converts `DiscoveryMemoryGroup` into `MemoryRecord` with `MemorySourceType.DISCOVERED_ONLY`.
- Converts `StoredAlbumSummary` into `MemoryRecord` with `MemorySourceType.ORGANIZED_ALBUM`.
- Keeps discovery-only records out of `AlbumSummaryHistoryStore`.
- Keeps discovery-only detail based on `DiscoveryPhotoRef.sourceUri`.
- Provides read-only lookup:
  - `memories()`
  - `memory(memoryKey)`
  - `discoveryPhotoRefs(memoryKey)`
- Merges records only when the exact `memoryKey` already matches.
- Does not guess that an organized album and discovery group are the same memory based on title, country, city, or folder name.

Important boundary:

- No UI wiring yet.
- No `MainActivity` change.
- No Gallery album creation.
- No writes to organized album history.
- No Personal Place candidate generation.

## Gemini Review Follow-Up

Gemini review agreed with the MVP direction and highlighted pre-release risks:

- permission loss / invalid `sourceUri`
- stale or missing discovery refs
- discovery-only records accidentally being treated as organized history
- confusing CTA labels
- large snapshot parsing latency

Applied immediately:

- Added tests that detail ignores empty `sourceUri` values.
- Added tests that photo/open/organize actions are disabled when every source ref is stale or missing.

Deferred intentionally:

- Full Android permission-revocation UI handling. This needs the actual UI wiring path.
- `DiscoverySnapshotJson` schema hardening. Current store already has corrupt-file backup recovery/refusal; schema validation should be a separate storage patch.
- Large-library performance benchmark. This should be measured after the first UI entry point exists.

Pre-Play checklist for Memory Browsing MVP:

1. Existing album organization flow still works unchanged.
2. Discovery-only memory is labeled as app-internal viewing, not a Gallery album.
3. Detail handles deleted/permission-denied source photos without crashing.
4. Discovery-only records are never written to `AlbumSummaryHistoryStore`.
5. Home/history entry does not block on large snapshot parsing.
6. Back/home navigation returns cleanly from memory list and detail.
7. `앨범으로 정리` remains an explicit optional CTA.
