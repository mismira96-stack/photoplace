  - Fixed earlier in the background-sort stabilization flow.

  - Added explicit choice dialog.
- Sort history could show counts before actual file movement was complete.
  - Resolved by reconciling stored summaries against live album state.
- Result/history Home tab sometimes did not return home.
  - Fixed top-level navigation guard.

  - Reduced startup/prefs loading and summary work.

  - Reconciled against live MediaStore.
- Home original cleanup card existed but was pushed below memories.
  - Reordered it above overseas memories when pending cleanup exists.
- Sort result screen was slow with a large already-sorted test set.
  - Root cause: result rendering eagerly built a large original-cleanup URI list with repeated uniqueness checks.
  - Fixed by rendering only counts and loading URIs lazily on cleanup action.
- Sort result header showed `0` completed items while album rows were visible.
  - Root cause: header used only in-memory recently-sorted markers.
  - Fixed by falling back to live duplicate/already-sorted counts and groups.
- Broad POI fallback created noisy album names such as cafes, lakes, schools, stations, and access point names.
  - Fixed by keeping only a small allowlist and falling back to administrative names otherwise.
