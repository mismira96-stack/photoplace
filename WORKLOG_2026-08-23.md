# PhotoPlace Worklog - 2026-08-23

## Urgent discovery history fix

### Symptom

- After analyzing folder A, changing the selected source to folder B and analyzing again removed folder A memories from Discovery.
- The released Display First flow therefore behaved like a latest-preview cache instead of persistent discovery history.

### Root cause

- `DiscoverySnapshotController` mapped the latest preview and called `DiscoverySnapshotStore.save()` directly.
- Each successful analysis replaced the entire `discovery_snapshot.json` file.

### Fix

- Added `DiscoverySnapshotMerger` as a separate data-layer component.
- A new analysis now replaces only records whose source URI was part of that analysis.
- Records from previously analyzed folders are preserved.
- Reanalyzed URIs are replaced with their latest place metadata.
- A URI that is now duplicate/already organized or has no location is removed from Discovery.
- Groups, counts, date ranges, cover URI, and country metadata are rebuilt after merging.
- `MainActivity` remains thin; snapshot merge behavior is not implemented there.

### Home acknowledgement

- Opening Discovery now acknowledges the transient home completion result.
- Only in-memory preview state is cleared.
- The persisted Discovery snapshot is not deleted, so cards, search, detail, and location-album creation remain available.

### Navigation wording

- The Discovery tab is now labeled `발견 기록` to make its accumulating-history role clear.


### Recovery note

- Memories already overwritten by the released version cannot be reconstructed from the current snapshot file.
- After this fix is installed, analyzing the previously selected folders once restores them and later folder analyses preserve them.

## Post-release observation / next P0

- Reinstalling the app preserves Gallery-backed `위치 앨범` history but clears the app-private Discovery snapshot. This is expected for the current file location, but the user-facing recovery flow is not complete.
- Analysis completion currently reports a file count (`앱에서 볼 항목 N개`), while users need to know which **places** were newly discovered.
- Next P0 is `LocationAnalysisCache`, not a blind skip list:
  - cache normalized location results as well as no-location results;
  - reuse them to rebuild visible discovery records without a new Geocoder pass;
  - keep changed/new/GPS-added media as mandatory cache misses;
   - include a separate `이번에 새로 발견한 장소` section at the top of Discovery.
